# Manual NSO Local Install

Covers everything needed to install Cisco NSO locally on macOS and get a running instance.

---

## Prerequisites

### Java (openjdk@21)

NSO requires Java. Install and pin openjdk@21:

```bash
brew install openjdk@21
```

Add to `~/.zprofile` (or `~/.bash_profile`):

```bash
export PATH="/opt/homebrew/opt/openjdk@21/bin:$PATH"
export JAVA_HOME="/opt/homebrew/opt/openjdk@21"
```

Apply immediately:

```bash
source ~/.zprofile
java -version   # should show openjdk 21
```

### Installer binary

You need `nso-<version>.<os>.<arch>.installer.bin`.

If you downloaded a signed bundle (`nso-*.signed.bin`) instead, extract it first:

```bash
# Run in a scratch directory — the signed.bin drops cert files alongside the tarball
mkdir ~/Downloads/nso-extract && cd ~/Downloads/nso-extract
sh ~/Downloads/nso-6.7.darwin.arm64.signed.bin
# Produces: nso-6.7.darwin.arm64.installer.bin (and cert files)
```

## Step 1 — Run the local installer

```bash
NSO_VERSION=6.7
INSTALL_DIR="$HOME/nso-$NSO_VERSION"

sh ~/Downloads/nso-${NSO_VERSION}.darwin.arm64.installer.bin \
  "$INSTALL_DIR" \
  --local-install
```

What this does:
- Installs NSO binaries, libraries, YANG models, example packages, and bundled NEDs into `~/nso-6.7`.
- Creates `~/nso-6.7/ncsrc` — a shell script that sets `PATH`, `NCS_DIR`, `PYTHONPATH`, `MANPATH`, `DYLD_LIBRARY_PATH`, etc.

---

## Step 2 — Source the NSO environment

```bash
source ~/nso-6.7/ncsrc
```

This must be done in every terminal session before using NSO commands. To make it permanent, add to `~/.zprofile`:

```bash
echo 'source "$HOME/nso-6.7/ncsrc"' >> ~/.zprofile
```

Verify the environment is loaded:

```bash
which ncs        # should show ~/nso-6.7/bin/ncs
which ncs_cli
which ncs-netsim
ncs --version
```

> **Note:** `ncsrc` references `DYLD_LIBRARY_PATH` which may be unset in a clean shell. If you use `set -u` in your own scripts, wrap the source with `set +u; source ncsrc; set -u`.

---

## Step 3 — Create a runtime instance

NSO separates the software install from the running instance. The runtime directory holds the config, database, logs, and packages.

```bash
RUNTIME_DIR="$HOME/nso-run-6.7"

ncs-setup --dest "$RUNTIME_DIR"
```

What this creates:

```
~/nso-run-6.7/
  ncs.conf          ← main configuration file
  ncs-cdb/          ← CDB (configuration database)
  logs/             ← ncs.log, developer.log, audit.log, etc.
  packages/         ← symlinks to installed NED/service packages
  state/            ← NSO internal state
  scripts/          ← custom scripts hook
  README            ← quick-start reminder
```

---

## Step 4 — Start NSO

> **Critical:** Always `cd` into the runtime directory before starting NSO. Running `ncs` from any other directory causes `Cannot access directory ./state` (exit code 21).

```bash
cd ~/nso-run-6.7
ncs
```

Check status:

```bash
ncs --status | grep -E '^status'
# expected: status: started
```

---

## Step 5 — Connect to the NSO CLI

```bash
cd ~/nso-run-6.7
ncs_cli -u "${NSO_ADMIN_USER}" -C
```

`-u "${NSO_ADMIN_USER}"` authenticates as the admin user (set via `$NSO_ADMIN_USER`, password via `$NSO_ADMIN_PASSWORD`).
`-C` selects Cisco IOS XR-style CLI (instead of Juniper-style).

Basic CLI commands:

```
admin@ncs# show ncs-state version        ← NSO software version
admin@ncs# show packages package         ← loaded packages / NEDs
admin@ncs# show devices list             ← managed devices
admin@ncs# show running-config           ← full NSO config
admin@ncs# exit
```

## Step 6 — (Optional) Enable RESTCONF API

By default RESTCONF is disabled. To enable it, edit `~/nso-run-6.7/ncs.conf`.

Find and change the `<restconf>` block:

```xml
<!-- Before -->
<restconf>
  <enabled>false</enabled>
</restconf>

<!-- After -->
<restconf>
  <enabled>true</enabled>
</restconf>
```

Also enable the WebUI TCP transport (search for `<webui>` → `<transport>` → `<tcp>`):

```xml
<tcp>
  <enabled>true</enabled>
  <port>8080</port>
</tcp>
```

Restart NSO to apply:

```bash
cd ~/nso-run-6.7
ncs --stop
ncs
```

Test RESTCONF:

```bash
curl -su "${NSO_ADMIN_USER}:${NSO_ADMIN_PASSWORD}" \
  -H 'Accept: application/yang-data+json' \
  http://localhost:8080/restconf/data
```

WebUI: `http://localhost:8080` (login: `$NSO_ADMIN_USER` / `$NSO_ADMIN_PASSWORD`; the password is generated by `install_nso_local.sh --start` and saved in `<runtime>/nso-admin.env`)

---

## Step 7 — (Optional) Enable development mode

Development mode disables the production license requirement:

```bash
cd ~/nso-run-6.7
ncs_cli -u "${NSO_ADMIN_USER}" -C 'license smart development enable'
```

---

## Step 8 — Verify the installation

```bash
# Directories
ls ~/nso-6.7/ncsrc          # must exist
ls ~/nso-run-6.7/ncs.conf   # must exist

# Commands available
which ncs
which ncs_cli
which ncs-setup
which ncs-netsim

# NSO running
cd ~/nso-run-6.7
ncs --status | grep status  # status: started
```

---

## Day-to-day commands

```bash
# Start NSO
cd ~/nso-run-6.7 && ncs

# Stop NSO
cd ~/nso-run-6.7 && ncs --stop

# Restart NSO
cd ~/nso-run-6.7 && ncs --stop && ncs

# Open CLI
ncs_cli -u "${NSO_ADMIN_USER}" -C

# Check logs
tail -f ~/nso-run-6.7/logs/ncs.log
tail -f ~/nso-run-6.7/logs/developer.log
```

## Directory reference

| Path | Purpose |
|---|---|
| `~/nso-6.7/` | NSO software install (binaries, libraries, YANG) |
| `~/nso-6.7/ncsrc` | Shell environment script — source this |
| `~/nso-6.7/packages/neds/` | NED packages installed here |
| `~/nso-6.7/examples.ncs/` | Bundled example projects |
| `~/nso-6.7/doc/` | HTML documentation |
| `~/nso-run-6.7/` | Runtime instance (config, CDB, logs) |
| `~/nso-run-6.7/ncs.conf` | Main NSO configuration |
| `~/nso-run-6.7/ncs-cdb/` | CDB — persistent device/service config |
| `~/nso-run-6.7/logs/` | All NSO logs |
| `~/nso-run-6.7/packages/` | Symlinks to active NED/service packages |
